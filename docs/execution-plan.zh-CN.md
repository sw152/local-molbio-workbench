# 自动执行计划

每个阶段遵循相同规则：先实现可运行的最小闭环，再用合成数据测试并以私有导出做本地验证；通过后提交、推送并自动转入下一阶段。公开仓库只保留代码与合成测试数据。

| 阶段 | 状态 | 自动交付 | 完成门槛 |
|---|---|---|---|
| 0. 导入与证据 | 已完成 | Benchling ZIP、哈希、重复成员、解析警告 | 原始数据可追溯，警告可审阅 |
| 1A. 质粒审阅 | 已完成 | 圆形 feature 图与图例 | 真实圆形记录可渲染，警告明确显示 |
| 1B. 设计数据骨架 | 进行中 | revision、primer、job、audit 数据对象 | 旧导入可自动补齐 revision，API 可查询 |
| 1C. 引物设计 | 已完成 | Primer3 候选、结合位点、筛选参数 | 从 revision 生成并保存候选引物 |
| 1D. 引物工作流 | 已完成 | 选择、命名、订购/送样导出 | 已选引物可导出且来源可回溯 |
| 2. Sanger 验证 | 待开始 | ab1 读取、比对、覆盖和报告 | 正反向 reads 产生可审阅结论 |
| 3. 全质粒测序 | 待开始 | 队列、长短读适配器、共识与变异 | 批量任务可恢复、结果可追溯 |
| 4. 实验室部署 | 待开始 | PostgreSQL、账户、项目和审计 | 多人部署和备份恢复演练通过 |

## 已搭好的长期对象

- `sequence_revisions`：每条导入序列自动生成不可变 revision 1；人工编辑只创建后续 revision。
- `primers`：候选与已选引物都关联一个明确 revision，保存指标和设计参数。
- `analysis_jobs`：引物设计、Sanger、全质粒分析都用同一任务状态与输入/输出清单。
- `audit_events`：记录对象发生了什么变化，为多人版的审计打基础。

这四个对象是后续功能的稳定边界。UI、Primer3、ab1 解析、GPU worker 和多人权限可以迭代替换，而历史证据链保持不变。

工作站、Tailscale Serve、Tailscale SSH 与多节点 worker 的边界见 [工作站指南](workstation-tailscale.zh-CN.md)。
