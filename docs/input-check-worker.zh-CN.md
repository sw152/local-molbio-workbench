# 已登记 AB1 的单次输入检查 worker

阶段 3 现在有一个可执行的队列闭环：提交已上传的 AB1 ID → 领取任务 → 检查参考和文件身份 → 保存结果或失败原因。它不运行比对、共识或变异分析；`succeeded` 仅表示输入检查完成。结果明确保存 `analysis_performed: false`、`whole_reference_verified: false` 和 `scope: registered_input_integrity_only`。

## 在同一个数据目录下操作

应用与命令必须使用同一 `MOLBIO_DATA_DIR`。下列命令在项目 Python 环境执行；本项目实际执行主机仍是 M2。`REVISION_ID` 和 `READ_ID` 应替换为该实例已有的真实 ID，不是文件路径。

```sh
python -m localmolbio.worker enqueue-check --revision REVISION_ID --read-id READ_ID --key UNIQUE_REQUEST_KEY
python -m localmolbio.worker once --worker-id m2-input-check --lease-seconds 60
```

多个输入可以重复提供 `--read-id`，一项任务最多 100 个不同读段，全部必须属于指定修订。提交排序后的输入清单，使同一集合不同排列不会制造不同请求；每项保存读段 ID 和登记的 SHA-256，以及参考修订 ID、SHA-256、拓扑。请求键遵循队列幂等规则，返回原任务并不代表重新排队；有意重跑使用新键。`--max-attempts` 范围为 1–10，默认 3。

`once` 最多领取一项 `registered-ab1-input-check-v1` 任务，结束后退出。没有兼容任务输出 `idle`，不启动常驻服务。未知 adapter 不执行，也不会将请求中的字符串视为命令。除内部 Python 接口和 CLI 外，已提供 [修订范围内的提交 API 与任务界面](input-check-ui.zh-CN.md)；批量上传仍未实现。

退出码：提交被接受（包括已有请求）、idle 或输入检查成功为 0；本次尝试失败或丢失租约为 1；无效提交/参数为 2。`attempt_failed` 是本次尝试失败，任务可能因可重试 I/O 问题重新进入 queued，并不必然表示预算已耗尽。现有 `/api/jobs` 可查看顶层任务状态；专用输入检查详情 API 现已提供分页尝试历史。

## 检查内容与边界

1. 参考序列的实际 SHA-256 必须与数据库一致，修订身份/哈希/拓扑还必须与提交快照一致。
2. 每项输入必须仍是对应修订已登记的 AB1，且登记哈希没有改变。
3. 路径须位于当前实例的受管理 reads 目录内。拒绝符号链接、目录及 FIFO 等非普通文件，不接受调用方提供的任意路径。当前文件打开使用 POSIX `O_NOFOLLOW` / `O_NONBLOCK`，已在 M2 macOS 验证；尚未提供 Windows worker 支持。
4. 按 1 MiB 分块计算实际 SHA-256，并核对打开前后文件描述符及最终路径的设备、inode、大小、mtime、ctime，避免读取过程中替换或修改文件却保存成功。
5. 读文件前及各块之间续租，计算完成后再次检查数据库身份；最终发布由队列的当前 token 和到期时间约束。若 I/O 阻塞超过租约，恢复后会丢弃此次结果，不在后台偷偷延长失效租约。

检查是逐文件、某个时间段内的身份核对，不是整个文件集合的原子文件系统快照；成功后外部仍可能修改文件。后续测序适配器执行前必须再次验证身份，或使用其独立不可变输入快照。此检查不重新解析 AB1，也不确认峰图、碱基调用或生物学结果正确；上传时已解析的记录只在这里做文件身份复核。

成功结果只保存参考身份、读段 ID、实际哈希和字节数，不复制原始输入，不输出信号或序列，也不泄露存储路径。已知失败保存稳定的错误代码；未知异常只保存 `unexpected_input_check_error`，避免将路径或输入内容写入通用任务错误。

文件缺失、哈希变化、错误修订、目录/FIFO/符号链接等为终止性错误。一般 I/O 异常可以在预算内重试；没有自动重试循环或退避守护进程，需要下次显式 `once` 领取。取消只是撤销发布权，尚未实现终止外部计算进程；当前适配器没有外部子进程。

## 本轮验收

20 项输入检查/worker 专项回归通过：真实合成 ABIF 字节、多个输入的稳定顺序及末项损坏不发布部分成功、文件缺失/变更、参考序列/拓扑及读段归属变更、受管理目录边界、符号链接/目录/FIFO、读取中变更、可重试 I/O 的历史、取消/租约失效、未知异常脱敏、未知 adapter 不执行，以及独立 CLI 进程的成功、idle、拒绝和失败退出码。

首次测试发现目录被当作可重试 I/O 错误；已调整为打开后先 `fstat` 判断普通文件再包装流，并确保每条退出路径关闭文件描述符。目录与 FIFO 现在终止失败而非重复重试。

全量 258 项 Python、11 项 Node 测试通过。M2 Chrome 合成 AB1 流程及移动端/离线 HTML 截图复核通过；本轮不重复公开样本验证。测试过程不生成 Sanger 分析报告，也不修改成功检查的原始文件。
