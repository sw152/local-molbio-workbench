# V1：同数据对照、初次使用与持续使用验收

状态：**已排入正式计划，尚未开始用户试验；没有时间收益、成功率或留存结果。**

2026-10-07 用户明确要求优先安排：同一批数据比较是否节省人工时间、是否可靠、初次能否独立完成、数周后是否愿意继续使用。V1 是多人部署、库存和 AI 扩展前的决策门槛，技术测试通过不能替代此验收。

## 顺序和启动条件

| 顺序 | 工作 | 结束条件 |
|---|---|---|
| V0，当前开始 | 固定任务定义、记录表、样例选择标准与候选指标 | 本文可用于收集数据；空白项明确待测 |
| 试用就绪，紧接当前审阅工作 | 区间到原始证据定位、最小可导出报告、首次安装/启动说明、受限现有分析器的可用执行入口 | 普通试用者无需开发者代操作或手写 SSH/worker 命令完成所选任务；工具缺失有可理解的处理路径 |
| V1-A，就绪后优先 | 锁定一批参考与测序文件，做可靠性和 Benchling 同任务技术对照 | 输入清单、版本、参数、真值和差异记录齐全；未支持任务单列，不伪装成成功 |
| V1-B，首次自愿试用 | 5–10 位目标研究者的初次使用与人工时间对照 | 逐人记录完成情况、提示/代操作、耗时和失败原因 |
| V1-C，个人首次试用后第 7/14/28 天 | 真实重复使用观察和简短复盘 | 记录自然发生的任务、是否主动回来、是否改回 Benchling，以及原因 |
| V1-D，第 28 天资料到齐后 | 采用/缩小定位/继续修复的决策 | 根据四类证据逐项判断，列出下一轮最小改进，不直接扩大功能面 |

不能等全质粒共识、多人或所有设想完成才开始 V1。先选当前能诚实支持的质粒/Sanger 验证闭环；有界 FASTQ 局部证据可作为另一项独立任务，不宣称它具备未实现的完整测序结论。试用就绪补齐项只服务这个闭环，不新增无关分析器。

D0 按每位试用者首次实际开始日期记录，不从今天或邀请日期起算。尚未有参与者及开始日期，不能虚构日历复盘或把持续收到 heartbeat 视作持续使用。真实试用启动后，现有自动检查应检查到期的 D7/D14/D28 记录；缺失反馈标为缺失，不能自动补成成功。参与者联络或提醒须另有用户明确授权，本计划不授权发送消息或招募。

## 固定同一批数据和同一任务

预先冻结参考修订、原始文件哈希、案例编号、两端软件版本和工作流说明。原文件与个体记录放在 M2 项目忽略目录 `var/product-validation/`，不加入公开仓库。公开仓库仅保存方案、空白模板和可公开的合成样例。

案例覆盖：干净匹配、明确差异、低质量、冲突/混合证据、重复位置、圆形跨起点、覆盖不足和错误文件/参考关联。先以独立真值核查的合成案例测边界，再用允许本地使用的去标识真实文件测体验。现有开发回归样例可作预检，但还需预留未参与实现调试的案例，不能挑选有利样本作为总体结果。

两工具共同可完成的任务采用完全相同的输入和交付目标：正确关联参考，找出指定异常或证据不足区域，定位原始证据，输出可复核的审阅记录。某端不支持原始格式或某一分析步骤时记录功能缺口和真实转换/准备成本，不能忽略、不把失败计作零秒，也不把不同任务输出拿来比速度。不能以 Benchling 的结果自动当成真值；有分歧时单独人工复核，未解决则标为无法判断。

每位参与者尝试两工具，交替安排先后顺序，并记录既有熟练度与重复看到同一数据的学习影响。提供同等简短任务说明和文档；区分“允许查文档”和“接受他人提示/代操作”。同数据交叉试验的记忆效应需要在结论中说明，不能简单宣称差异全部来自工具。

## 四项判据

| 维度 | 必须记录 | 预设候选门槛与解释 |
|---|---|---|
| 人工时间 | 首次设置、主动操作、等待计算、总完成时间、点击/文件往返、失败及重做 | 以重复任务的逐人配对主动时间为主要指标，候选目标为中位数减少 50%；同时公布全部配对值和失败，不拿最快一次作结论。首次设置成本单列但不能藏掉 |
| 可靠性 | 严重错误、漏检、误报、正确标为不确定、无法判断、原始证据可追溯性 | 范围内测试出现错参考、错坐标导致错误解释、把未覆盖/不确定认作通过等严重错误，即先阻断扩展并修复。报告每类分母，零观察错误不等于证明零风险 |
| 初次独立完成 | 从安装/启动到报告，是否完成、在哪卡住、文档查阅、提示/代操作次数 | 候选门槛：至少 80% 开始试用者无需他人提示/代操作达成预定正确结果。必须以所有开始试用者为分母，同时报告人数；退出者不得被删除，开发者代操作不算独立完成 |
| 持续使用 | D7/D14/D28 实际任务机会、自主使用次数、是否返回其他工具和原因 | 候选门槛：D28 有相关任务机会的参与者至少 60% 主动回来完成另一项真实任务。同时报告全体人数、无任务机会人数、失访人数；提醒后的演示不算自然复用 |

上述为小规模探索试验的预设候选门槛，不是统计显著性证明或已经达到的指标。收集前固定；若后续修改门槛，保留原门槛、变更理由和原结果，不事后挪动标准来制造通过。没有相关任务机会或失访既不能认定失败原因，也不能计作留存成功。

首次独立完成的分母为所有开始该任务的试用者；表中 80% 指其中达到正确结果且无他人帮助的比例。不得改用“完成者中的独立比例”掩盖失败。

## 记录模板

每个试验任务一行（当前无真实记录）：

| 字段 | 填写规则 |
|---|---|
| participant_id / task_id / dataset_id | 匿名编号；私有清单关联原文件哈希，不公开真实研究名 |
| tool / version / order / prior_experience | 工具、版本、先后顺序和既有熟练度 |
| started_at / setup_seconds / active_seconds / waiting_seconds / total_seconds | 实际计时；停顿和中断写明原因 |
| completed / correct / help_count / takeover | 分开记录“做完”和“做对”；帮助与代操作不得留空 |
| false_positive / false_negative / severe_error / unresolved | 按预设真值和范围记录；不能用空值代表零 |
| evidence_path / friction / return_reason | 私有证据路径、卡点、选择继续或返回其他工具的原因 |

持续使用另按 participant_id、D0、checkpoint、真实任务机会数、自主完成数、提醒/协助、替代工具及原因、反馈是否缺失记录。脚本/代理跑出的基准只进入技术测量，不能冒充人类首次体验、人工时间或采用意愿。

## 不达标后怎么做

1. 可靠性出现严重错误：阻断扩展，先修正确性并用独立案例复验；速度收益不能抵消错误结论。
2. 慢或不易上手：按卡点优先修参考关联、批量入口、默认流程、异常跳转、安装和报告，不通过增加功能数量补偿。
3. 短期能用但没有主动复用：核查任务频率、目标人群和返回原因，缩小到确有优势的高频任务；不能把“觉得不错”当成留存。
4. 四项证据不足：阶段保持待验证，可继续有依据的修复和试用准备，不自动进入多人或 AI 扩展。若优势仅在本地/隐私场景，明确收窄定位，不宣称对所有 Benchling 用户更优。

决策记录需包含：观测结果与分母、未完成/无法判断项、用户原话的去标识摘要、结论、下一轮最多三项具体修复及复测任务。用户数据不因开发测试通过而自动获得公开授权。
