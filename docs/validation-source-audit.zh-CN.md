# 真实对照前：输入清点与配对资格

本步骤解决“有很多参考文件，是否就足够验证测序”的问题。文件可解析、序列数量多或峰图可显示，都不等于存在可信的参考—原始读段配对，更不等于已证实准确性。

## 有界、只读的输入清点

```sh
python scripts/audit_validation_source.py /private/path/export.zip \
  --output /private/path/new-inventory.json
```

脚本不解压、不修改归档、不导入应用数据库、不推断参考配对，也不联网。输出归档身份、文件/记录数量、扩展名、固定类别的分子类型和拓扑、ABIF/SCF 文件头计数、重复成员名数量及解析警告/失败。报告不含序列、注释、成员名和路径；归档哈希仍属于数据身份，真实报告留私有目录。

上限：压缩输入 128 MiB，ZIP 条目 10,000，单条目解码 32 MiB、总解码 512 MiB；超限或加密条目明确拒绝。嵌套归档与其他未识别格式列为 opaque，不递归展开。ABIF/SCF 魔数只表示疑似格式，并未验证它可以解析；空 GenBank、解析失败或部分记录后失败不能转换成“没有数据”。readiness 始终为 not_established，配对需要额外的显式关系。

多条 ZIP 成员可以同名，必须分别统计；归档中的文件数、记录数、唯一名称数和独立构建数不能互换。需要配对时以归档哈希、成员序号/同名出现次数、记录序号和参考序列哈希共同定位，不以文件名猜配对或覆盖同名输入。

## 配对清单的最低条件

每项私有案例需要原始 AB1 字节哈希、明确的参考记录身份与序列哈希、拓扑、配对依据、允许的本地使用范围和预期要验证的区域。实验证据或经独立确认的参考优先；不能拿 read 自身的碱基构造参考，再宣布比对准确。若实际只有局部验证任务，就预先指定目标区域，未覆盖区域继续标为未验证。

对照真值与测试工具结果分开：构造账本、独立测序/人工核验或独立审阅者来源可用，但需说明限制。只有 Benchling 中“看起来匹配”的标签不能直接成为真值。参考注释被解析器修复时，保留警告，检查跨起点位置、方向、复合注释和原始导出；不静默把修复后的坐标当作原始事实。
