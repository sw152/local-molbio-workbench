# 输入检查任务 API 与界面

构建详情底部的 **Input integrity checks** 面板支持选择当前修订已经上传的 AB1，提交一项含 1–100 个不同读段的输入完整性检查。桌面以选择区和任务区并排显示，窄屏改为纵向。详情优先显示读段文件名，下面保留 ID、哈希和尝试历史。

这不是批量上传或测序分析。上传仍在上方 AB1 区域进行；页面入队后等待同一数据目录的本地 worker，使用既有 `python -m localmolbio.worker once` 执行。页面不隐式启动后台进程，也不提供任意命令执行接口。当前点击 **Refresh checks** 更新状态，没有自动轮询。过期租约由后续 worker 领取或显式恢复处理，查看任务不会修改队列状态。

## 修订范围内的接口

以下前缀均为 `/api/revisions/{revision_id}/input-checks`。

| 操作 | 路径 | 行为 |
|---|---|---|
| POST | 空路径 | 接受 `read_ids`、`idempotency_key`、`max_attempts`（默认 3）；固定使用受限输入检查适配器，额外字段被拒绝 |
| GET | 空路径 | `limit` 1–100（默认 5）与 `offset` 分页，返回最新任务优先的列表、total 和 has_more |
| GET | `/{job_id}` | 同一读取快照中的状态、输入清单、结果和分页尝试历史（最新尝试优先） |
| POST | `/{job_id}/cancel` | 只取消该修订的输入检查；取消可重复，成功/失败任务不改写，返回 409 |

跨修订或不同适配器的任务详情和取消均为 404。非法输入为 422，同一幂等键绑定不同请求为 409。读段名称来自当前登记记录供显示，ID/哈希来自保存的任务清单，不声称名称是提交时快照。接口不返回文件存储路径、幂等键、lease_token 或其作为内部尝试 ID 的副本；尝试对外用 number 表示。保留 worker 名称、状态、时间和错误代码供审阅。这些是单机个人版接口，未增加账户或多人权限体系。

## 前端状态处理

- 已选数量超过 100 或没有可用读段时不能提交；提交/刷新/取消期间禁用重复操作。
- 如果服务端已入队但网络响应丢失，同一修订和选择集合的重试保留原请求键，避免重复创建任务。键保存在当前页面进程内存中；完整刷新浏览器后不会持久保留，刷新后应先检查已有任务再有意重提。
- 切换或关闭构建时递增请求版本，所有迟到响应都不能填入新构建；不在新构建展示旧任务详情。
- 刷新失败保留已有列表并显示错误，允许重试；不会把网络失败显示成空任务列表。列表与尝试历史各自分页。
- 任务完成明确标为 **Input check complete**；详情和面板说明均明确没有运行序列分析。取消撤销结果发布权，尝试历史仍保留。

## 验收

6 项新增 API 回归通过：入队幂等、状态/结果、内部 token 不泄露、修订及适配器隔离、7 项任务和 7 次尝试的分页、queued/running 取消、跨读段和未知字段拒绝、参数边界与键冲突。全量 264 项 Python、11 项 Node 测试通过。

M2 Chrome 使用隔离合成数据实际操作复核：选择两条读段；服务端成功入队但丢弃响应后重试只出现一项任务；独立 worker 进程执行并显示成功；查看文件身份与尝试；取消第二项任务；刷新请求失败后恢复；关闭构建后丢弃延迟详情；创建 7 次真实保存的失败尝试后查看两页历史。桌面、390 px、历史翻页控件及错误状态截图均人工检查。原 Sanger 上传、峰图、历史、导出和错误回归继续通过，未用 DOM 数量替代视觉验收。
