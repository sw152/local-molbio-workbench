# 用户为什么选择这个工具

2026-10-07 用户要求：完成开发后必须回答，为什么别人不用 Benchling，而选择我们。该问题成为交付验收门槛，也从现在开始约束范围。以下定位是待验证假设，不是已经证实的市场需求或竞品优势。

## 已核对的竞争基线

- Benchling 面向学术用户提供免费的 Notebook 和分子生物学功能，已有引物设计、克隆、比对等工具。“免费 + 引物 + 图谱”本身不能构成迁移动机。来源：[学术方案](https://www.benchling.com/academic)、[引物工具](https://www.benchling.com/primers)。
- Benchling 已有批量比对，且支持圆形模板、全质粒和跨起点比对。不能把我们刚完成的局部比对 UI 当成独有能力。来源：[比对工具](https://www.benchling.com/alignments)、[创建比对](https://help.benchling.com/hc/en-us/articles/39922093033869-How-to-create-alignments)。
- Benchling 官方说明访问和保存数据需要网络。由此可以提出本地/断网工作流的差异化假设；这不等于断言它的数据治理不安全。来源：[账户导航与离线说明](https://help.benchling.com/hc/en-us/articles/9684267691021-Navigate-your-Benchling-account)。

## 首个目标用户与产品承诺

优先服务经常做克隆和质粒验证、希望数据与运算留在自己电脑或实验室工作站、需要批量处理返回测序文件的研究者和小实验室。暂不以已经深度依赖 Benchling ELN、样品管理和组织协作的团队作为整体替换目标。

待验证的一句话定位：**把测序返回文件放进本地工作台，快速定位哪些构建、哪些区域需要人工复核，并能一路追溯到原始证据。**

潜在选择理由：

1. 本地拥有数据和运行环境：安装后核心导入、分析、审阅、导出不依赖外部云服务；本机模式要通过断网验收，远程 UI 模式仍需要到工作站的网络。
2. 减少重复点击：从一批返回文件到样本清单、参考关联、覆盖缺口、差异定位和审阅报告的完整工作流。重点测量人工操作时间，而不只比算法运行时间。参考自动关联不确定时应要求确认，不能静默猜测。
3. 容易核查和重跑：结果关联原文件、参考修订、软件版本、参数和不确定性，能直接定位原始峰图或读段证据。不能把“开源”直接等同于准确，必须有独立真值和对照验证。
4. 可按实验室流程接入：通过稳定 CLI/API、开放格式、可复现配置连接已有脚本；标准操作无需用户写代码。GPU 和模型训练只有在可测量地改善任务时才加入。

上述四项不应全部宣传为已完成。现阶段已有数据身份、部分 Sanger 证据链与有界 FASTQ 比对闭环；通用安装、真正省事的批量验证、覆盖/共识及完整离线验收仍需补齐。

## 降低试用成本

首先允许与 Benchling 并用：从导出的 GenBank 和测序文件开始完成一项验证任务，不要求重建实验记录或迁移整个实验室。保留原文件、标准导出和明确的导入损失说明。普通工作流应能在无 SSH/命令行经验的研究者机器上安装、启动和重开项目；不能把开发者自己能运行当成产品可用。

精致图谱、错误恢复、明确坐标与可读报告是信任和使用门槛。功能数量、自动迭代次数、测试数量或“支持 AI”都不作为采用理由。

## 验证门槛与后续顺序

先完成当前覆盖与审阅闭环，再做一次产品验收，之后再决定是否扩大多人框架：

- 用有明确真值的合成样例，以及经允许本地使用的去标识真实返回文件，覆盖干净、低质量、混合/冲突、重复、跨起点和不完整测序。记录遗漏、误报及无法判断，未覆盖不能记为通过。
- 与 Benchling 在相同输入、同一任务目标下比较：安装/准备成本、主动操作分钟数、点击数、误关联数、异常定位时间、报告可复核性。把“省至少一半人工操作时间”作为候选目标而非既有性能结论；比较后据结果调整。
- 验证初次用户能从安装到导出报告独立完成流程，以及本地模式断网、退出重开和标准格式往返。导入不能只证明记录数一致，还要查坐标、拓扑和注释。
- 邀请 5–10 位自愿试用者做自己的重复任务，观察是否愿意连续数周回来使用、哪些步骤仍返回 Benchling。当前没有进行访谈、招募、对外消息或真实留存测量。
- 若只因界面新鲜试用、仍需大量命令行操作，或没有节省人工时间，则收缩和改进核心工作流；不靠增加多人、库存或 AI 功能掩盖价值不足。

阶段交付时同时报告“新增能力”和“解决的实际用户问题”。完成上述验证前，不宣称能取代 Benchling、不声称已有广泛受众。

正式阶段顺序、同数据对照设计、候选判据和 D7/D14/D28 记录方法见 [V1 用户价值验收方案](product-validation-plan.zh-CN.md)。该阶段现已列入总计划，优先于多人或 AI 扩展。
