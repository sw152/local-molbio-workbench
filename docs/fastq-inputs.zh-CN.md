# FASTQ 输入登记与流式检查

现在可通过 API 为一个参考修订登记原始 FASTQ 文件并获取格式、长度与质量摘要。FASTQ 使用独立的 `fastq_inputs` 表，不将几百万条记录塞入单条 Sanger read，也不会出现在 AB1 峰图或 Sanger 覆盖统计中。当前尚未提供 FASTQ 上传界面、FASTQ 队列适配器、比对、共识或变异分析。

## 接口与证据

- `POST /api/revisions/{revision_id}/fastq-inputs`：multipart 字段 `file` 和必填 `quality_encoding=phred33`。支持 `.fastq`、`.fq` 及其 `.gz` 扩展名；压缩魔数必须与扩展名一致。返回原始文件 SHA-256、字节数、压缩类型、登记身份与摘要，不返回存储路径、序列或读段标题。
- `GET /api/revisions/{revision_id}/fastq-inputs?limit=10&offset=0`：在同一数据库快照下分页列出该修订的登记记录（最新优先），limit 为 1–100。不存在修订为 404，非法格式为 422，同一修订重复字节内容为 409。
- 摘要含记录/碱基数、最短/最长/平均读长、N 和全部 IUPAC 模糊碱基数、最小/最大/平均 Phred、Q20/Q30 碱基数、实际解压字节数及校验限制。平均 Phred 是碱基质量分数的算术平均，不是平均错误概率。
- `analysis_performed: false`、`whole_reference_verified: false`，scope 为 `fastq_format_and_quality_summary`。全部记录目前按 `single_file_unpaired` 处理；不根据文件名或标题推测 R1/R2，也不猜测仪器或长短读平台。

质量编码必须由调用方明确声明 Phred+33。字符范围 33–126 被解释为 Q0–Q93；Phred+64 等编码与其字符范围可能重叠，无法靠字符判断声明是否正确，因此不自动探测或转换。请依据数据来源选择正确编码；当前不接受其他编码。

## 格式边界

解析器按字节流读取，允许序列和质量跨多行，质量行即使以 `@` 或 `+` 开头也按剩余长度读取，不误判成新记录。可使用 LF / CRLF，最后质量行可以没有换行。可重复的 `+` 标题必须与 `@` 后的完整标题一致。头部允许可打印 ASCII 与制表符，标题不能为空；序列支持大小写 DNA IUPAC `ACGTRYSWKMBDHVN`，不接受 RNA U、空读段或序列中的空白。低质量和模糊碱基保留计数，不裁剪、补齐或纠正。

质量总长度必须与序列长度相同。空文件、截断、非法字符、额外无效尾部、超出长度和数量限制均拒绝整次登记，不返回只验证前一部分的成功。gzip 必须完整通过解压和 CRC 检查，支持标准的串联 gzip members。摘要只说明文件符合这里定义的受支持语法，不是所有历史 FASTQ 变体的兼容承诺。

默认限制：原始文件 2 GiB、解压流 8 GiB、每条 read 4 Mi bases、每文件 1,000 万条记录。每次仅保留一行及累计计数，不把全文件或所有序列放入内存；换行分段也累加检查每条 read 的总长度。底层 Python 接口 `FastqLimits` 可供部署方调整；API 暂未开放用户任意放大限制。原始大小限制在应用接收暂存文件时检查，不等于 HTTP multipart 入口的总体请求限额；框架会先接收/暂存 multipart。

## 保存、并发与中断

文件先在当前 `MOLBIO_DATA_DIR/fastq/.incoming` 私有暂存，复制时计算原始字节 SHA-256，完整验证通过后以哈希命名保存。gzip 的哈希对应上传的压缩字节，不是解压内容；不同压缩包装可能得到不同身份。

使用不覆盖已有文件的硬链接发布，再在数据库事务中保存登记与审计；同一修订重复内容只有一个登记。不同修订可以引用同一个原始内容文件。已有目标文件要先核对哈希才能复用；发现外部修改或符号链接就拒绝，绝不覆盖已有数据。常规错误会清理本次暂存文件。进程被强制终止可能留下暂存或未登记的内容文件；文件系统和数据库不是跨系统原子事务，当前不做自动删除或垃圾清理，后续使用前仍需验证身份。

上传文件名只作为元数据保存，不用于拼接落盘路径。数据、原始文件、数据库和报告均不进入公开 Git 提交。本项目实际执行和保存仍在已获授权的 M2 内置工作区。

## 验证依据

本轮以安装的 Biopython `FastqGeneralIterator` 文档核对换行和重复标题规则，并用 Biopython FASTQ 解析结果对照 20 条合成分段记录的数量与质量统计。没有复制用户研究序列作为公共测试。样例覆盖 CRLF、无末尾换行及质量行起始 `@`/`+`。

26 项新增测试覆盖 Q19/Q20/Q30、IUPAC 模糊碱基、低质量保留、空文件、序列/质量长度、无效字符、gzip CRC/截断/串联、压缩名不符、各资源上限、并发去重、不同修订、原始字节保留、已有文件被改动时拒绝、清理与分页。尚未用实际仪器 FASTQ 或大规模生产数据做兼容性和性能验收。

下一步为这组接口增加精致的 FASTQ 上传/摘要面板和浏览器错误流程，随后接入队列身份复核，再引入真正的长短读分析器。不要把格式检查或 Q20/Q30 数量直接解释成覆盖、测序准确性或质粒通过。
