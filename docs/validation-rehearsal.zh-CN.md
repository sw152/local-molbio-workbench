# V1 对照包 01：冻结输入，先做技术预演

状态：只有公开合成输入和空白记录，没有 Benchling 对照结果、独立用户或持续使用证据。此包以 Sanger 审阅为主，FASTQ 局部证据另设任务，不能混算为同一种完成时间。

## 生成与冻结

在源码包已安装依赖的环境运行：

```sh
python scripts/build_validation_pack.py --output /absolute/private/path/v1-sanger-rehearsal-01
```

本项目执行仍在 M2；生成物保存到项目忽略目录 `var/product-validation/`。输出目录必须不存在，脚本不覆盖旧包或观察记录。固定种子、GenBank 日期、ZIP 时间戳；`manifest.json` 包含每个文件的大小与 SHA-256，`manifest.sha256` 锁定清单。核查源代码版本和清单后冻结；输入变更必须新建版本，不覆盖旧结果。记录表从模板另存，不修改冻结包中的模板。

仅交给试用者 `participant/`：包含同一套 GenBank、AB1、参考导入 ZIP 和中立任务表。ZIP 是本工具导入便利项，两个工具均使用相同的单个 GenBank/AB1；导入方式、转换与准备成本据实记录。不要给试用者 `evaluator/`，其中是生成操作与预期证据。目录分离仅帮助组织，**不构成访问控制或真正盲法**；主持人须分开发放。答案公开可查，此包不能声称未见留出集。

AB1 使用既有编码器生成人工峰形；逐碱基质量是人为设定，不能用于证明真实仪器解析普适性、混合峰判读或 base calling 准确性。A04 是两个读段互相冲突，不是模拟同一个色谱中的混合峰。真实混合峰和去标识仪器文件仍待授权选择与独立审阅，不能用此包替代。

## 参与者任务（两工具完全一致）

对任务表中每项：确认指定参考和文件身份，查看所有读段，找出差异或证据不足之处，定位原始证据，并保存另一位研究者可复核的记录。记录坐标约定、方向、质量和未覆盖区域；无法判断时写明原因。不得只交一个“通过”标记。

允许查同等简短说明和各工具文档；帮助、提示和代操作都要记下。开始前记录工具版本、参数、机器、已有熟练度与顺序。原始分析使用 unknown 方向、不裁剪；若某工具不允许相同设置，记录差异，不能假称参数相同。可另做 Q20 端部裁剪复核，但与首次原始分析分开计时。遇到格式不支持或卡住，保留失败和花费时间，不删除该参与者/案例，不把失败记为零秒。

以每个案例的完整交付为计时边界，主动操作、等待、首次设置单列。合成案例不代表日常任务比例；逐类列出结果，不从此包推断整体真实工作节省。两工具顺序按匿名参与者交替安排；同一输入重复看到的学习效应必须记录。不要让参与者先看评分答案。

## 评估者规则

生成账本使用 0 基半开坐标；页面可能使用 1 基显示。评分先转为同一坐标，再比较。不得因为显示约定差异误判，也不得忽略真实一位偏移。真值来自构造操作，还需另一位审阅者核对；当前 `independently_reviewed=false`。工具输出只作被评估证据，不能反向修改预期来让测试通过。

| 案例 | 预设需核查的证据 | 严重错误举例 |
|---|---|---|
| A01 | 干净局部匹配，仍有未覆盖 | 把局部完美匹配说成全质粒通过 |
| A02 | 反向替换、原始 read 坐标、质量 | 方向/坐标误定位导致错误解释 |
| A03 | 低质量差异与低质量两端 | 把 Q9 差异当作已确认突变 |
| A04 | 两份读段高质量但互相冲突 | 隐藏冲突，声称已有共识 |
| A05 | 两处完全重复的位置 | 无依据声称唯一定位 |
| A06 | 圆形跨起点的两段及未覆盖 | 丢掉起点一侧或扩大覆盖 |
| A07 | 80 bp 短局部匹配，1120 bp 未覆盖 | 宣称构建已验证 |
| A08 | 错参考；偶然短局部匹配仍可能存在 | 用偶然命中确认正确构建 |
| A09 | 错误文件被拒绝，可继续操作 | 错误文件有成功分析/错误结果 |
| A10 | 反向插入、边界和原始 read 区间 | 插入被当作参考覆盖或错锚点 |

对于插缺等价位置，先用原始序列重建核验等价性，保存原报告坐标和理由，不擅自归一化。未支持项单列为功能缺口；解释准确性和功能可用性不能混成一个“通过率”。无分歧证据的项目标为待复核，不能自动给满分。

## 记录与决策

复制 `session-template.json`、`observation-template.json`、`retention-template.json` 到私有观察目录。每个案例、每个工具一条 observation；未测字段保持 null，不能当作 0。技术代理预演的 record_type 必须是 technical_rehearsal；人类实际完成后才用 human_session。没有真实参与者时人类记录应保持空集。

D0 来自实际首次试用，D7/D14/D28 仅在真实日期到达并收到观察时填写。记录任务机会、主动完成、提醒/协助和失访；提醒演示不算主动复用。此包不招募、不自动发消息或设定虚假的 D0。

正式候选门槛及失败处理沿用 [V1 方案](product-validation-plan.zh-CN.md)：主动时间配对中位数减少 50%、全部开始者独立正确完成至少 80%、D28 有相关任务机会者主动复用至少 60%；均是待验证目标。任何严重错误先阻断扩展。若不同工具尚不能完成相同任务，应先收窄比较范围并公开缺口，不产生误导速度比。

下一步是独立复核合成账本、选择未参与调试的案例与可本地使用的真实 AB1、实测两个工具支持情况，再开展真实独立试用。发布包/测试通过本身不意味着 V1 通过。
