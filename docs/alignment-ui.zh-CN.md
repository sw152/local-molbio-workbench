# FASTQ 局部比对提交与审阅界面

构建详情的 FASTQ 登记面板下方新增独立的 **FASTQ alignment** 面板。它连接 [任务 API](alignment-api.zh-CN.md) 和 [有界比对 worker](registered-fastq-alignment.zh-CN.md)，不把 FASTQ 文件摘要或任务成功解释为质粒通过。

## 操作

1. 在上方登记 FASTQ / FASTQ.gz，并声明质量编码。点击 Refresh alignment tasks 同步新增登记文件。
2. 选择本修订的文件（每页 5 个，跨页保留选择，最多 100 个）；显式选择 ONT noisy / ONT high accuracy / PacBio HiFi / unpaired short reads。类型没有默认值，不根据文件名自动推断。
3. Queue alignment 创建任务。提交不会启动后台 worker；需由本机配置好的 `python -m localmolbio.worker once --adapter alignment` 执行。网页不会接收或执行任意命令/二进制路径。
4. Refresh alignment tasks 更新状态，Review alignment 打开尝试和结果。queued/running 可以取消；取消后的迟到 worker 不能发布结果。无自动轮询或隐含重试。

任务、尝试和读段结果每页 3 项。任务列表按新到旧，尝试按序号降序；读段按本次 qN 查询顺序（文件 ID 排序、文件内顺序）展示。每个记录都有原文件名、登记 input_id、1 基文件内记录序号和大写序列哈希，重复 FASTQ 标题不会合并记录。摘要中的文件名仅为标签，哈希和 ID 保留内容身份。

## 图与科学边界

每个局部命中显示正/反向、参考区间、原始 read 区间、跨起点状态、exact identity、已比对读段比例、错配、插入/缺失和模糊配对数。图轨以实际 paired_blocks 绘制彩色片段，删除区间保留空隙；它不是质量感知覆盖图。参考顺序从左向右，箭头表示原始读段相对参考的方向；圆形跨起点命中在两端分段显示，不连成一个跨全参考的色块。

图与文字统一使用 **0 基半开区间**，与其他面板可能使用的 1 基坐标分开明确标注。窄屏图轨保持 700px 最小宽度以保留刻度字号，可横向滚动和键盘聚焦，页面外层不横向溢出；下方完整文本坐标不依赖滚动。所有命中均可展开 CIGAR 与原始 primary/secondary、MAPQ；本轮没有逐碱基差异编辑、图轨缩放或总覆盖统计。

跨参考一圈以上的证据显示 Evidence withheld · review，并保留原因；未报告可用命中显示 No alignment reported。多重匹配需审阅；单条命中也明确未评估唯一性，候选搜索不穷举。原始 MAPQ 未为圆形双拷贝重新校准。局部 identity 包括 N 和 gap 列，不能作为全质粒通过阈值。

界面持续标明质量与配对未参与当前比对、没有共识或全质粒验证。32 MiB 原始/解压总量、5,000 reads / 5M bases、100kb 单读段及 200kb 参考等上限在提交区展开可见；超限整项拒绝，不截前缀。

## 错误与异步恢复

网络/服务失败保留已有任务、文件选择和审阅内容，并明确说明显示信息可能过时。提交响应丢失时，以同一修订、选择和类型在当前页面会话中重试复用请求键；成功确认后才清除选择。刷新或切换页面后，尚未确认的键没有持久化到磁盘，因此不承诺浏览器重启后的自动幂等恢复。

关闭/切换构建会增加 generation，迟到的文件列表、任务、详情、读段和提交响应不能污染新修订。操作期间禁用当前面板控件，避免重复并发操作；仍可关闭构建。不同类型或选择视为新请求，用户需要保留未知提交的原选择后重试。

## 验收

`scripts/verify_alignment_ui.py` 在 M2 启动独立临时应用和 Chrome，使用合成 FASTQ 与真实固定 minimap2。覆盖显式类型、提交响应丢失后重试只产生一个任务、worker 执行、正反向/跨起点坐标、6 bp 缺失图间隙、两圈读段 withheld、未报告命中、文件跨页选择、任务/尝试/读段分页、取消、列表失败恢复、迟到详情/提交隔离，以及窄屏内部横向滚动和外层不溢出。图形检查同时保留实际截图并人工查看，不仅依赖 DOM 数量。

已有 Sanger/任务和 FASTQ Chrome 完整回归继续通过；384 项 Python（配置真实 minimap2，无集成跳过）、11 项 Node 测试通过。没有实际仪器数据或大规模性能结论。
